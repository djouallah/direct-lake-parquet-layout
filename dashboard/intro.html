Every engine deals with two formats: the format on disk, and the format in memory where it actually computes.

With a proprietary format, the engine's developers design both. The disk format is made for that engine, so it reads it directly, with minimal effort.

The lakehouse decouples them. The disk format is open (Parquet, with Delta or Iceberg on top) and any engine can write it. So every engine that reads it has to do some work to turn it into its own in-memory format. In Power BI, that work is called transcoding.

How much work depends on how the file was written.

Proprietary format

SQL Server, an import-mode Power BI model: the engine writes its own format and reads it back as written. No translation.

The trade-off: the data is read through that engine, or copied for each other tool.

The lakehouse

One copy in OneLake. Any engine writes it, any engine reads it.

The trade-off: the file is not shaped for any particular reader. The writer's settings decide that, and most writers default to what suits the writer.
